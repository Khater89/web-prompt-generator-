# Supabase backend — Project Forge

هذا المجلد جاهز لإضافة خلفية Auto وتحليل المشروع وبحث الويب إلى Project Forge.
الواجهة تتصل بوظيفة `ai-assist`، والوظيفة تتصل بـOpenAI من الخادم. لا يلزم
تسجيل دخول لاستخدام هذا الربط. المفتاح العام يعرّف المشروع؛ ليس مفتاحًا سريًا.

## 1. إعداد SQL

في مشروع Supabase افتح **SQL Editor**، وانسخ ونفّذ:

`migrations/202610040001_research_limits.sql`

ينشئ عدّادات خاصة للطلبات: 20 محاولة بحث للمشروع و5 لكل عميل خلال 10 دقائق.
العدادات مشتركة بين نسخ الوظيفة؛ لا تعتمد على ذاكرة نسخة خادم واحدة.
الحصة العامة تبقى فعالة حتى لو تغيّر عنوان العميل. العداد العام يحتسب محاولات
البحث المقبولة مبدئيًا، بما فيها المحاولات التي تفشل لاحقًا. لا تُحفظ وثائق PRD
أو أوصاف المشاريع في قاعدة البيانات. يُحفظ عدّاد وبصمة مملّحة لعنوان العميل فقط.
الوصول إلى عدّادات SQL ووظيفتها مقتصر على خدمة الخلفية، مع تفعيل RLS ومنع anon.

## 2. إعداد Secrets

افتح **Edge Functions → Secrets** وأضف:

| الاسم | القيمة |
| --- | --- |
| `OPENAI_API_KEY` | مفتاح OpenAI الخاص بك؛ يُدخل داخل Supabase فقط |
| `OPENAI_MODEL` | `gpt-5.4`، أو نموذج متاح لحسابك يدعم web_search والمخرجات المنظمة |
| `FORGE_ALLOWED_ORIGINS` | رابط الواجهة كاملًا بدون شرطة أخيرة |
| `FORGE_PUBLIC_KEY` | المفتاح العام publishable أو anon الذي ستستخدمه بالواجهة، إذا لم تكن مفاتيح Supabase المحقونة تشمل هذا المفتاح |

رابط الواجهة المنشورة الحالي:

https://project-forge-khater.abdelrahman-khater-e.chatgpt.site

يمكن السماح بعدة روابط بفصلها بفاصلة، مثل إضافة `http://127.0.0.1:8080` للتجربة.
فتح index.html مباشرة يستخدم origin باسم `null`؛ استضافة الواجهة عبر HTTP/HTTPS
أفضل. لا يُسمح بـnull إلا إذا أضفته صراحة. لا تستخدم `*` بدل الرابط.

Supabase يحقن `SUPABASE_URL` ومفاتيح الخلفية تلقائيًا. لا تنقل service_role أو
sb_secret أو مفتاح OpenAI إلى الواجهة. مفاتيح SUPABASE_* ليست Secrets مخصصة
يُعاد إنشاؤها هنا. النموذج المحدد مهيأ في المثال وليس اختبارًا لصلاحية حسابك.

## 3. نشر الوظيفة

### من محرّر Supabase — ملف واحد

1. افتح Edge Functions ثم أنشئ أو عدّل الوظيفة باسم `ai-assist` باستخدام المحرّر.
2. افتح `functions/ai-assist/index.ts` من هذه النسخة وانسخ **محتواه كاملًا**.
3. استبدل محتوى `index.ts` في محرّر Supabase بالمحتوى الجديد، ثم اضغط Deploy function أو Deploy updates.
4. عطّل Verify JWT في إعدادات الوظيفة، ليكون مكافئًا لـ `verify_jwt=false` في config.toml. الكود يتحقق من المفتاح العام في apikey بنفسه.

ملف index.ts الجديد يحتوي جميع أجزاء الخلفية في داخله، بدون أي import لملفات
_shared. يمكن نشره وحده. لا تحتاج رفع _shared مع طريقة المحرّر. تظل ملفات
_shared مصادر للتعديل وتوليد الملف المجمع، وليست اعتماديات عند تشغيل الوظيفة.

إذا ظهر Module not found مع ../_shared، فالمحرّر ما زال يستخدم index.ts القديم.
استبدل **الملف كله** وليس السطر الأول فقط. تابع إعداد SQL وSecrets الموضح أعلاه؛
تصحيح التجميع لا ينشئ مفاتيح API ولا ينفّذ SQL تلقائيًا.

### من CLI

من مجلد المشروع الرئيسي الذي يحتوي `supabase/`، وبعد تثبيت Supabase CLI:

```sh
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy ai-assist
```

ملف `config.toml` يضبط `verify_jwt=false` لدعم المفتاح العام الحديث الذي ليس JWT.
الوظيفة تتحقق من المفتاح العام داخل الكود ومن origin المسموح، وتطبق حصة SQL
قبل أي طلب مدفوع. CORS والمفتاح العام لا يوفران مصادقة شخصية؛ هذا ربط بدون
تسجيل دخول، وهو محدود بعدادات الطلبات. اضبط ميزانية خدمة AI حسب استخدامك.

إذا كنت تستخدم migrations بدل SQL Editor، يمكنك تنفيذ `supabase db push`،
مع مراعاة أي migrations موجودة مسبقًا في مشروعك. ملفنا ينشئ كائنات بأسماء
محددة ولا يحذف بيانات التطبيق. تنفيذ نفس الملف يعيد إعداد الوظيفة والصلاحيات.

## 4. ربط الواجهة

في Project Forge افتح **إعداد اتصال الخلفية**:

1. اختر **Supabase**.
2. ضع **Project URL** مثل `https://PROJECT.supabase.co`، أو رابط الوظيفة الكامل مثل `https://PROJECT.supabase.co/functions/v1/ai-assist`.
3. ضع **Publishable / anon key** العام.
4. اضغط **حفظ وفحص الاتصال**، ثم اكتب المشروع واضغط **Auto**.

لا تضع مفتاح OpenAI في هذه الخانة؛ الواجهة ترفضه وترفض مفاتيح service_role.
الإعدادات العامة تُحفظ في متصفحك. أعد هذه الخطوة على أي متصفح جديد.

عنوان الوظيفة: `PROJECT_URL/functions/v1/ai-assist`.
الفحص يستخدم `GET ?action=status`. البحث يستخدم `POST` مع بيانات المشروع.
الفحص يؤكد إعداد الخلفية وإمكانية الوصول؛ أول Auto يختبر SQL وخدمة AI فعليًا.

## إذا بقي Auto غير مفعّل

- اختر Supabase في «إعداد اتصال الخلفية» واحفظ Project URL والمفتاح العام.
- أضف FORGE_ALLOWED_ORIGINS بالقيمة المطابقة لرابط الواجهة، بدون المسار أو شرطة أخيرة.
- خطأ 401: راجع المفتاح العام وتعطيل Verify JWT. خطأ 404: راجع اسم ai-assist ونشرها.
- إذا وصلت الوظيفة وكانت Secrets ناقصة، يعرض الفحص أسماء الإعدادات الناقصة فقط.
- بعد إكمال Secrets، اضغط حفظ وفحص الاتصال أو Auto؛ تعيد الأداة الفحص تلقائيًا عندما لا يكون الاتصال جاهزًا.
- جاهزية الفحص لا تؤكد SQL أو صلاحية حساب OpenAI؛ أول طلب Auto يختبرهما فعليًا.

## محتويات المجلد

- `functions/ai-assist/index.ts`: الوظيفة كاملة بملف واحد، مناسب للمحرّر وCLI.
- `functions/_shared/handler.mjs`: CORS، التحقق، الحصة، وفحص الاتصال.
- `functions/_shared/research.mjs`: بحث فعلي ثم تحليل منظم بالمصادر.
- `functions/_shared/schema.mjs`: التحقق من اكتمال الناتج.
- `migrations/202610040001_research_limits.sql`: جدول الحصة ووظيفتها.
- `functions/.env.example`: أسماء الإعدادات بدون مفاتيح حقيقية.

البحث مرحلتان، وله مهلة 125 ثانية حتى تعود رسالة واضحة قبل حد Supabase للطلب.
الطلبات الملغاة أو الفاشلة لا تغيّر اختيارات الواجهة ولا تُعرض كنجاح. إغلاق
المتصفح لا يضمن أن مزود AI أوقف فوترة عملية بدأت بالفعل.

## حالة التحقق

اختُبرت الوظيفة وربط الواجهة بردود API اختبارية، بما فيها نجاح البحث ورفض
المفتاح أو origin، وفشل SQL، وحد الحصة، وغياب Secrets. لم تُنشر في حساب Supabase
بعد، ولم تُختبر بمفتاح OpenAI حقيقي، ولم يُنفّذ SQL على قاعدة Postgres حية هنا.

عند تعديل البحث الأصلي في server/ شغّل:

```sh
node scripts/sync-supabase.mjs
```
